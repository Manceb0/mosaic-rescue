# WHY matplotlib IS 3.8.4 AND NOT 3.7.2
#     The figures were originally rendered with matplotlib 3.7.2, which has no
#     cp312 wheel on any platform: the copy on the production machine carries a
#     cp312-win_amd64 tag, so it did not come from PyPI and could not be
#     installed by anyone else. That made the whole environment
#     unreproducible, which is a real defect and not a formatting detail.
#
#     Resolved by moving to matplotlib 3.8.4, which does publish cp312 wheels
#     for Linux, macOS and Windows, and then re-rendering all nine publication
#     figures and comparing them pixel by pixel against the 3.7.2 originals:
#
#         9 of 9 figures, 0 differing pixels, maximum channel deviation 0
#
#     The swap is therefore visually a no-op, verified rather than assumed.
#     Reproduce that check with `python src/verify.py` plus
#     `python src/figures/render_all.py` on a machine holding the dataset.
#
# WHY numpy IS PINNED BELOW 2.0
#     The matplotlib wheels used here are compiled against the NumPy 1.x ABI.
#     Installing NumPy 2.x breaks the whole plotting stack with
#     "numpy.core.multiarray failed to import". This is not a preference; the
#     figures do not render without it. Verified the hard way during this
#     project when an unrelated install pulled NumPy up to 2.5.2.
